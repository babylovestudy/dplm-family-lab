# DPLM-1 150M的PF00194家族生成式适配与评估

报告日期：2026-10-16。**正式协议已完成：三次1,000步训练、12组各256条生成评估、4组固定噪声test去噪及严格来源核对齐备，`formal_status=complete`、缺失阶段为0。** 适配后家族profile命中提高，同时最近训练identity增加、生成集配对距离下降；本实验支持家族分布适配，未验证结构或酶活。正式结果与100步pilot分开记录。

可复查入口：[严格汇总说明](experiment-summary/README.md)、[配对分析JSON](analysis/formal/analysis.json)、[比较CSV](analysis/formal/generation_comparison.csv)、[逐序列诊断](diagnostics/formal/README.md)和[104份正式小型证据索引](formal/index.json)。

## 1. 问题与研究范围

本实验考察：在公开预训练蛋白序列模型DPLM-1 150M上，使用PF00194（α型碳酸酐酶）家族序列继续训练，能否提高指定长度范围内生成序列的家族profile匹配率；这种变化是否同时伴随序列多样性下降、训练近邻相似性增加或精确复制。

任务是家族分布上的生成式适配，没有活性回归头、活性标签或湿实验。家族信息来自适配数据，不通过文字提示输入。评价对象是序列与家族profile的兼容程度、生成集多样性及与适配训练集的关系，不以HMM命中代表催化活性、结构正确或新酶发现。

代码与复现入口为[项目仓库](https://github.com/babylovestudy/dplm-family-lab)。原理说明见[模型指南](../docs/model-guide.md)，完整单阶段命令见[实验协议](../docs/experiment-protocol.md)。

## 2. 数据、版本与冻结重建

### 2.1 来源与筛选

数据为2026-10-16获取的UniProtKB **2026_03**快照，数据库发布日为2026-09-02。查询条件为PF00194注释、长度180–256 aa及非fragment记录。该长度范围用于限制首个单卡实验的成本，会排除家族中其它长度的成员，不代表完整PF00194分布。

使用Pfam **PF00194.27** HMM，模型长度255，sequence与domain的GA阈值均为27 bits；至少一个通过GA的独立domain需覆盖≥80%的模型位置，即至少204个位置。多个短domain的覆盖不会相加。

| 数据处理阶段 | 序列数 |
| --- | ---: |
| 原始UniProt查询记录 | 4,464 |
| 去除非标准氨基酸 | 13 |
| 去除精确重复 | 91 |
| 清洗去重后，均通过GA | 4,360 |
| 因单domain覆盖不足排除 | 1,418 |
| 最终合格序列 | 2,942 |

筛选阈值与原始数量见[data-preparation.json](data-preparation.json)。同一个HMM既用于数据完整性筛选，也用于生成家族评测，因而后续的家族命中是与任务目标一致的profile指标，**不是独立功能验证**。

### 2.2 同源隔离与划分构成

采用Biopython全局最优比对：match=1、mismatch=−1、gap open=−2、gap extend=−0.5。identity为相同残基数除以全部比对列数，包含内部和末端gap；两侧coverage分别为含两侧残基的列数除以各自完整序列长度。双方按序列SHA确定规范方向，得分并列时取第一个最优比对。

identity≥0.8且双向coverage≥0.8的配对连边，再按传递连通分量整体拆分；长度比例和二肽多重集上界只排除数学上不可能达标的配对，不以近似候选检索替代严格检查。最终有1,719个分量，最大分量61条。

| 划分 | 序列数 | 分量数 | 构成说明 |
| --- | ---: | ---: | --- |
| train | 2,354 | 1,131 | 用于继续训练和生成长度分布 |
| validation | 294 | 294 | 均为当前80/80阈值图中的单序列分量 |
| test | 294 | 294 | 均为当前80/80阈值图中的单序列分量 |

分配以整分量和接近目标80/10/10序列比例为准，按分量大小降序处理，split seed为42。因此validation/test的singleton构成是本次划分的实际特征，需要在解释泛化时保留，不能笼统称为随机独立抽样。

跨集合审计覆盖1,470,588对，安全筛选后精确检查43,304对，发现0个满足上述阈值的跨集合违规配对。该结论仅限给定指标和阈值，不排除远同源，更不证明测试序列未出现在基础模型的预训练语料中。详细定义和逐条accession/序列hash见[数据报告](README.md)与[frozen-splits.json](frozen-splits.json)。

## 3. 模型与生成式继续训练

### 3.1 固定来源

| 对象 | 固定身份 |
| --- | --- |
| 官方源码 | `bytedance/dplm@8a2e15e53416b4536f03f79ad1f6f6a9cbd5e19d` |
| 原始权重 | `airkingbd/dplm_150m@49b7125a5d28c6418fcc2f3c4fe799352ac1488b` |
| 原始权重文件SHA-256 | `ea4eaa99536b60ed76f945f71a1a5e604f08447ec3def5104a93ca6001a59961` |
| 实际可训练参数 | 148,796,794 |

本项目选择性移植DPLM-1网络、加噪和迭代采样实现，增加单卡训练、数据审计和来源校验，不复现UniRef50规模的从零预训练，也不把本地工作流称为官方原封不动的pipeline。移植范围见[本地来源说明](../src/dplm_family_lab/_vendor/SOURCE.md)。

### 3.2 训练目标

干净序列为`x0`。每条序列随机采样`t∈{1,…,500}`，普通残基以`t/500`概率替换为MASK得到`xt`；BOS/EOS/PAD位置受保护。双向Transformer由`xt`预测原始token，仅在实际被掩码的残基上计算交叉熵，时间权重为`w(t)=(501−t)/500`。每个microbatch的加权损失按其掩码位置数归一化，零掩码情形作有限值安全处理，再进行梯度累积。

这是更新模型本体的全参数生成式适配，不是冻结模型提取embedding、训练外接回归头或LoRA。模型的[加噪/去噪实现](../src/dplm_family_lab/_vendor/model.py)、[安全损失](../src/dplm_family_lab/backend.py)和[优化循环](../src/dplm_family_lab/training.py)可直接核对。

### 3.3 预先固定的训练协议

实际L4配置对应公开的[pf00194-l4.yaml](../configs/pf00194-l4.yaml)。原始运行用机器专用runtime副本，将`model.source`改为已核验的本地缓存`model_cache/dplm_150m`；科学参数相同，原始配置随各run保存。不能在恢复或重建汇总时把旧run的模型来源字符串静默改成公网ID。

| 项目 | 正式设置 |
| --- | --- |
| 训练种子/优化预算 | 42、43、44；各1,000个优化步 |
| microbatch/梯度累积 | 4×4，有效序列batch为16 |
| 优化器 | AdamW；基础学习率1e−5，weight decay 0.01 |
| 学习率与裁剪 | warmup 50步，之后按实现降至基础学习率一半；gradient clip=1 |
| 精度与激活 | NVIDIA L4，BF16，启用gradient checkpointing |
| 验证与保存 | 每100步；检查点选择仅依据固定噪声validation去噪loss |
| 验证/测试噪声种子 | 9173 / 9174；不消耗训练随机流 |

Gradient checkpointing通过反向重算中间激活换取显存，与磁盘恢复检查点不同。有效batch相同也不意味着不同microbatch划分的梯度轨迹逐位相同；随机掩码、dropout和归一化方式都需保持在运行协议中。

## 4. 配对生成与评测

### 4.1 生成矩阵与输出约束

正式对照有4个arm：原始模型baseline，以及训练种子42、43、44的三个适配模型。每个arm用生成种子101、102、103各请求256条，共12组、3,072条请求，其中baseline仅生成3组并被三个适配模型共享比较。训练种子与生成种子分开记录。

每个生成种子从训练集长度分布有放回抽样一次，四个arm复用同一长度列表及SHA，不从test选择长度。采样为100次迭代的`gumbel_argmax`，batch size为4；每批随机种子、offset、条数和最终FASTA均记入manifest。两臂均从残基位置全MASK开始，经并行预测、候选保留与重新掩码得到整条序列，不沿左到右逐字生成。

采样时预先屏蔽非20种标准氨基酸的词表项，包括ESM null token，训练logits保持原词表。这一规则在pilot和正式实验之前固定，四个arm一致，并在manifest记录`output_alphabet`；它是本地采样修改，不是事后按HMM结果选择性过滤，也不能称为未修改的官方采样输出。实现见[sampling.py](../src/dplm_family_lab/sampling.py)。

### 4.2 指标及分母

| 指标 | 定义与解释 |
| --- | --- |
| 有效/失败 | 原始请求、实际输出、标准氨基酸有效数、非法及缺失数分别记录；长度符合率单列 |
| GA率与家族率 | 在有效输出中统计GA通过比例、GA且单domain覆盖≥80%的比例；重复和长度越界记录仍保留在条件分母 |
| 整体家族产出率 | 家族通过条数/原始请求数，用于防止条件命中率掩盖生成失败 |
| 重复与精确复制 | 超额重复率=`1−唯一有效序列数/有效数`；精确训练匹配率为有效输出中与train完全相同的比例 |
| 最近训练identity | 对每条有效输出寻找train中全局identity最高的邻居，使用与数据审计一致的比对定义 |
| 生成集多样性 | 有效输出间平均`1−global identity`，重复序列的距离为0；不等于功能多样性 |
| 固定噪声test CE | baseline与三个适配模型在相同test、时间步与掩码条件下的加权掩码去噪指标；不是真实完整序列perplexity |

原始明细保留每条序列的HMM分数/覆盖、近邻ID/identity、重复与精确匹配标记。HMM低分、过近邻居和失败输出均应保留；如家族匹配提高而近邻identity同时升高，应与多样性和复制指标共同解释，不能只展示命中率。

### 4.3 统计单位与配对区间

每个训练种子×生成种子产生一项与对应baseline的配对比较，共9项。比较前核对生成种子、序列ID与顺序、长度清单内容/SHA、每批种子、请求数及采样规则。当前完整分析要求所有请求索引都有有效、长度一致的输出；不满足时拒绝完整配对分析，不能删去非法/缺失样本再制造含混区间。

对一项比较，以**同一生成序列索引**同时重采样两臂，进行1,000次bootstrap，给出适配减baseline的家族率差值及95% percentile区间。全有效时条件家族率与整体请求产出率分母相同，两种差值一致。分析固定PCG64随机流，主seed为20261016，并由训练/生成seed区分各比较的随机流；脚本版本、输入SHA和NumPy版本随分析保存，见[analyze_results.py](../scripts/analyze_results.py)。

各训练种子跨3个生成种子仅报告简单均值与范围，不把9组适配生成当作9次独立训练，不做p值。生成序列可能相关，序列重采样区间不覆盖所有训练不确定性；只有3个训练种子也不足以支持强泛化声明。零命中可能得到经验bootstrap的`[0,0]`，不能据此断言总体命中概率为0。生成集距离的区间按序列重采样，不将成对距离当作彼此独立观测。

训练恢复需保留整个run目录：`last.pt`、选定`best.pt`、tokenizer、验证噪声、配置和日志等，且当前实现要求checkpoint记录的原始绝对`output_dir`一致。迁移一个权重文件到新路径不等于可恢复原优化器状态；任意新路径恢复会被拒绝。`export_best`用于可移植推理，连同独立identity及provenance保留；具体文件和路径要求见[远程GPU说明](../docs/remote-gpu.md#取回与复现)。

### 6.1 家族匹配与固定噪声test去噪

identity和配对距离列为三个等大小生成组的均值再作简单平均，**配对距离不是把768条合并后重新计算全部跨组配对**。12个组各自内部都没有精确重复；baseline跨生成种子有两条序列各出现两次，故合并唯一数为766。九个适配组跨生成与训练seed合并后，2,304条序列均不同。

依据原始评估的最近训练邻居结果，全部适配输出的最近identity均低于80%，最高为0.703557；≥80%及≥90%的计数均为0。补充核值检查验证了所记录参考配对与精确复制标记，**没有重新执行全局最近邻搜索**，见[诊断说明](diagnostics/formal/README.md)和[配对核值记录](diagnostics/formal/reported_pair_verification.json)。

两臂的完整训练序列复制计数本来都为0，因此本实验只能说“本次采样未发现完整训练序列复制”，不能说“复制减少”或“减少记忆”。全局identity<80%也不能排除片段记忆；其它数据库、预训练语料及功能新颖性没有被验证。更直接的观察是：家族匹配提高伴随最近训练identity从约0.268升至0.565–0.573，配对距离从约0.796降至0.384–0.417，生成分布明显收窄，不能把“唯一序列数高”当作多样性保持不变。

### 6.6 本实验支持的结论

在固定PF00194子集、模型版本、长度分布和采样预算下，三个全参数适配模型均比原始模型生成更多符合该HMM条件的序列，并有较低的固定噪声test去噪CE。与此同时，最近训练相似性增加、生成集配对距离下降，说明家族匹配的提高伴随序列空间收窄。因而最初“提高匹配且不明显牺牲多样性”的组合目标不能直接判为满足。

本次输出没有完整训练序列复制，仍不足以排除片段或预训练记忆，更不能推导生物学功能提升。下一步可在新预先固定的验证方案下比较较少训练步数或更保守适配设置对多样性的影响，再决定是否进行独立结构与实验功能验证；这些步骤尚未执行。

## 7. 解释限制与后续验证

1. **评价与筛选共享profile。** 同一个PF00194 HMM用于数据筛选和家族评测；高命中仅说明更符合这个profile，不能作为独立功能证据。
2. **家族与长度范围有限。** 只研究一个家族的180–256 aa受限子集，不能外推到其它长度、家族、物种或生物学任务。
3. **划分控制有限。** 80/80隔离只排除给定指标下的近邻跨集配对；validation/test全为singleton components，后续可考察按分量随机分配的敏感性，不能把当前结果等同远同源泛化。
4. **预训练重叠未知。** UniRef50预训练可能包含本家族或测试序列，未证明“模型从未见过”或从零学习了该家族。
5. **统计重复有限。** 三个训练种子和三个生成种子区分报告；序列bootstrap为描述性采样区间，不能产生独立训练重复，更不能凭零命中区间断言总体概率为0。
6. **复制与新颖性不同。** 训练集精确匹配和最近邻是记忆线索，不是全数据库新颖性证明；家族匹配提高与近邻增加、多样性下降需要共同讨论。
7. **工程验证有范围。** 短恢复对照及CPU重载一致性针对记录的环境和设置；显存、耗时、固定噪声CE不能外推为任意硬件成本或真实生物功能。
8. **功能尚未验证。** 未进行结构、表达、稳定性和酶活实验，不能称为发现新酶或提升催化效率。后续验证应由完整序列诊断和明确假设驱动，而不是只挑HMM最高分样本。
