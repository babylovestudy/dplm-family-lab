# 第一周：把序列变成可训练的数据

这一周先不下载150M权重。目标是能亲手读懂 FASTA、写出简单数组操作，并解释“模型参数为什么会更新”。建议总投入10–15小时。

## 第1次学习：准备与认识项目（约2小时）

1. 在终端确认当前路径是 `dplm-family-lab`，记录 Python 版本。
2. 按README创建独立环境并安装基础包，运行 `dplm-lab doctor`。
3. 将检查输出分为“当前CPU练习必需”“后续真实数据必需”“后续GPU必需”。不要为了让检查全部变绿而盲目安装CUDA。
4. 阅读配置的 `data`、`train`、`generate` 三段。用自己的话解释：为什么序列长度、训练步数和生成条数是三个不同的量？

在本次已准备好的Windows工作目录中，可直接运行`.venv\Scripts\python -m dplm_family_lab doctor`，无需重建环境。`dplm-lab`短命令需要先激活对应环境；若提示找不到它，先使用上述完整解释器路径。远程训练目录已有的`.venv`是另一套Linux环境，不要和本机路径混用。

**你要提交：** 环境信息、遇到的问题、三个量的解释。无需GPU。

## 第2次学习：FASTA与数据质量（约2–3小时）

打开 [notebook](../notebooks/01_fasta_and_tensors.ipynb)，执行到FASTA解析和长度统计。示例是人为构造的短序列，不能用于碳酸酐酶研究。

本地尚无notebook工具时，可在已创建的CPU环境中另装JupyterLab，不需要PyTorch或GPU。以下为Windows项目根目录的命令：

```powershell
uv pip install --python .venv jupyterlab
.venv\Scripts\python -m jupyterlab notebooks/01_fasta_and_tensors.ipynb
```

没有uv时用`.venv\Scripts\python -m pip install jupyterlab`替代第一行。也可以使用已安装的notebook编辑器，但要选择本项目`.venv`中的Python作为kernel。先用“Restart Kernel and Run All”确认基础环境，再逐单元练习；不要只在GitHub预览页面阅读而以为已执行。

接着自己完成以下任务，先写思路再编程：

- 将一条序列拆成多行，观察解析器如何拼接。
- 新增一条含非法字符的记录，定位异常并解释为什么要拒绝它。
- 不抄库函数，写一个函数返回条数、最短长度、最长长度和平均长度。
- 思考两个不同ID拥有相同序列时，为什么随机拆分可能泄漏。

**验收：** 能指出header和sequence的区别；解释“文件能读出来”为什么不代表数据质量合格。

## 第3次学习：tokens与张量（约2–3小时）

执行notebook的token、padding、mask和shape示例。教学字典不是正式DPLM tokenizer，不要复制其编号到真实训练。

自己完成：

1. 在纸上画出2条不同长度序列组成的 `B × L` 数组。
2. 说明PAD为何不应作为预测目标，MASK为何表示被破坏的真实位置。
3. 将示例改成3条序列，推测输出shape后再运行核对。
4. 改变随机种子并比较mask位置；然后固定种子再次执行。

**验收：** 面对一个形状为 `(3, 7, 22)` 的教学logits数组，能解释每个维度；说明为什么22不是本项目真实DPLM词表大小。

## 第4次学习：损失与一次更新（约2–3小时）

执行NumPy交叉熵与梯度示例。它直接优化独立位置的logits，只展示梯度方向，**不是DPLM，也没有学会蛋白质规律**。如果已经安装PyTorch，可以运行可选的自动求导对照；没有安装时该部分会跳过。

不要只看“loss下降”。自己尝试并记录：

- 把学习率设为0，预测什么会变化、什么不变化。
- 改为只mask一个位置，说明为什么其它位置不应贡献损失。
- 解释 `backward` 与优化器更新不是同一个动作。
- 写下“loss下降仍然不能证明生成蛋白有活性”的两个原因。

**验收：** 能用一句话串起“预测→交叉熵→梯度→参数更新”，并解释这个玩具例子的局限。

## 第5次学习：独立复述与小作品（约2小时）

关掉示例代码，独立重新写出一个FASTA长度统计函数。再用5分钟向一个没有看过本项目的人解释：

1. 为什么先做FASTA和张量，而不是直接微调？
2. 微调后会改变什么文件，如何证明真的改变了模型？
3. 本项目最终想生成什么，暂时不能证明什么？

**本周完成标准：** 你有一页学习日志、一份自己写的统计函数、至少一次错误排查记录，以及上述问题的独立解释。仓库已有实现和notebook提供脚手架，不能替代这些练习。不要把“notebook全部运行成功”写成“已完成DPLM训练”。
